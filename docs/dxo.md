# DxO PhotoLab 10.1 适配

> 最终结论。逆向与实验过程记录在研究工作区，不在本仓库。数值都来自 `chart/SonyChart.ARW` 的导出测量和 PhotoLab 运行时读取。

## 1. 结构

和 Camera Raw 一样：**底座 DCP + 外观 3D LUT**。PhotoLab 能读 DCP 和 `.cube`，但不支持 XMP RGBTable。

    LUT(x) = 外观( E⁻¹(x) )         E：Sony 线性相机 RGB → LUT 输入

LUT 之后对色域内的颜色没有任何处理，所以 LUT 输出就是导出值：
- 灰阶上平方探针吻合到 0.03 级；
- 亮度探针三通道最大差 0.33 级。

## 2. 设置

| 项 | 值 |
| --- | --- |
| 颜色渲染 | DCP 配置文件 `SonyA7M5 Linear Base v2`，**DCP 曲线 Adobe**，强度 100，饱和色保护 0 |
| LUT | LUT 色彩空间 **ProPhoto RGB**，强度 100 |
| 其他 | 以"6 - 无校正"为起点：Smart Lighting、ClearView、对比度、镜头校正关闭 |
| 探针导出 | TIFF 16 位，ProPhoto RGB（嵌入 ROMM RGB），不勾 Preserve color details |

底座 v2：
- ColorMatrix1/2 用 Adobe Standard 的；
- ForwardMatrix1/2 都用 Adobe Standard 的 D65 ForwardMatrix；
- 影调曲线恒等，DefaultBlackRender = none，无 HueSatMap / LookTable。

v1 底座（ForwardMatrix = ProPhoto）会把相机原色当成 ProPhoto 原色，很多颜色落到光谱轨迹外，被 PhotoLab 多对一地压缩，所以弃用。

v3（v2 + BaselineExposureOffset −1.5）：
- PhotoLab 读这个标签，中间调正好暗 1.500 EV；
- 但高光处理的起点是按传感器电平固定的，压曝光绕不开，而且 lin 2429 起还有一段提亮；
- 所以也弃用。

DCP 曲线选"DxO"时，整体暗约 0.29 EV，暗部不单调，不用。

## 3. E（`dxo/dxo_model.py`）

    lin_sony（白平衡后的相机 RGB，Sony 刻度）
      → 高光恢复（仅当 max(lin) > 0.25·s3·K_G 时；s3 = 31742 时约 4092）
      → A：相机 → 线性 ProPhoto D50（6422 = 1.0）
      → DxO Wide Gamut：负分量裁成 0，再转回 ProPhoto
      → 每通道一维曲线（`dxo/e_curve_pure.csv`）→ ProPhoto γ1.8 编码

**高光恢复**（PhotoLab 的 WhiteBalanceRAW 阶段）：

    x = (512 + lin/K)·W/s3,  b = x·gain,  a = 0.75·max(x),  c = W·max(gain),  W = 32767
    out = b                                              (b < a)
        = min(a + (b−a)(W−a) / ((c−W)(b−a)/(c−a) + W − a), b)   (b ≥ a)

- K = (1.33545, 0.515625, 0.712891)，gain = K/K_G。
- s3 是 PhotoLab 的 WhiteLevel，**逐图估计**：
  - 在 raw 里找接近饱和、足够平坦的亮区，取其中最暗的均值；
  - 找不到时回退到传感器饱和值 2·(16383 − 512) = **31742**。
  - 普通照片基本都回退到 31742（DSC03591 和两张高 ISO 照片实测如此）；色卡、合成斜坡这类大面积平坦亮区才会得到 23623 / 24049 / 23585。
  - LUT 按 31742 生成。§3 的色卡精度是在色卡自己的 23623 下测的（`dxo_model.S3_CHART`）。
- 门槛比较的是**白平衡之后**的最大通道。
  - 按这个定义，色卡上未触发的 87 块和线性模型差 0.04 级；
  - 若按白平衡前 raw − black 判断，差 1.57 级。

**WG 负值裁切**：绿、蓝原色转到 DxO Wide Gamut 后有负分量，裁成 0 后较弱的通道被抬起。

| 单色斜坡 | 矩阵预测 | 裁切后 | 实测 |
| --- | --- | --- | --- |
| 红 | 1 / 0.246 / 0.255 | 不变 | 1 / 0.246 / 0.256 |
| 绿 | 0.321 / 1 / 0.004 | 0.326 / 1 / 0.050 | 0.328 / 1 / 0.052 |
| 蓝 | 0.218 / 0.001 / 1 | 0.218 / 0.023 / 1 | 0.227 / 0.035 / 1 |

**一维曲线**：用灰阶在"高光恢复之后"的值直接建表。
- 门槛以下就是 γ1.8、刻度 6422，误差 0.03 级。
- 门槛以上解码后，比值在 Lw 6000 处为 0.86，在 7200 处为 0.77。这说明高光恢复之后还有一段压缩，来源没有定位。
- 最后一个灰块之上，在线性域按最后一段的斜率外推。

**精度**（8 位编码值，264 块，去掉裁切块）：

| 区域 | 平均 | 最大 |
| --- | --- | --- |
| 门槛以下 | 0.11 | 3.4 |
| 门槛以上 | 4.56 | 26 |
| 门槛以上，仅灰块（建表样本，自评） | 0.32 | 0.9 |

门槛以上的误差全部在彩色块上：高光恢复之后那段压缩对彩色不是逐通道的，模型没有完整描述它。

## 4. E⁻¹ 与 LUT（`dxo/dxo_look.py`）

- E⁻¹ 用近似逆（曲线⁻¹ → A⁻¹）做不动点迭代，40 次。
- 往返误差：E(E⁻¹(E(lin))) 和 E(lin) 平均差 0.001 级，最大差 1.7 级。最大值出现在 WG 裁切造成的不可达区域。
- 结果钳在各通道的传感器饱和点内，然后依次经过 SSCS、外观链、sRGB → ProPhoto γ1.8。
- 网格 64³。在 DSC03591 上的离线插值误差（四面体插值，8 位 MAE）：

| 外观 | MAE | p99 |
| --- | --- | --- |
| ST / VV / NT / PT | 0.23 / 0.25 / 0.21 / 0.26 | 1.1–1.4 |
| FL / VV2 / IN / SH | 0.21 / 0.29 / 0.18 / 0.37 | 1.0–2.0 |
| BW / SE / FL2 / FL3 | 0.11 / 0.13 / 0.30 / 0.27 | 0.5–1.8 |

- 网格 48 时 ST 为 0.32，33 时为 0.54，所以保留 64。

## 5. 照片验证

DSC03591，ST，PhotoLab 导出 16 位 ProPhoto。对比对象是用拍摄时白平衡直接渲染的外观链。用 `compare_acr_export.py` 做多项式几何配准（PhotoLab 用了 ARW 内嵌的畸变校正，几何上与参考图差最多约 36 px），缩小 8 倍后比较：

| 项 | 值 |
| --- | --- |
| MAE | 1.18 |
| 整体偏差 R/G/B | +0.28 / +0.25 / +0.67 |
| p95 | 3.3 |

逐亮度段的偏差都在 ±1 级以内，只有 210–250 段的 R 为 +1.9（高光段）。

这段偏差来自 s3：用当时导出所用的 LUT，分别按两种 s3 预测这张导出：

| s3 | MAE | 210–250 段偏差 R/G/B |
| --- | --- | --- |
| 23623（色卡值） | 1.12 | +2.05 / −0.20 / +0.18 |
| 31742（这张图的实际值） | 1.09 | +0.37 / −0.28 / +0.07 |

其余亮度段两者完全相同（都在门槛以下）。所以 LUT 改为按 31742 生成；新 LUT 还没有在 PhotoLab 里重新导出验证。

注意：
- DSC03591 里保存的 Edit 设置是 6000K 白平衡。用 `sony_decode.py` 按保存的设置渲染出来的参考图，白平衡和 PhotoLab 的"拍摄时设置"不一样，不能直接拿来比。
- 还没有和 Edit 的 ST 导出做对照。

## 6. 自动导出

PhotoLab 可以不经界面批量导出：

1. 复制 ARW；
2. 写一个 `.dop`：`Name` 必须等于新文件名，Uuid 要新生成，导出记录要清空；
3. 用 `open -a` 打开；
4. 用 `osascript` 点"Image → Export to → Disk…"，再点"Export"。

导出格式沿用上一次的设置。新文件所在的文件夹没被 PhotoLab 重新扫描时，打开请求会超时（-1712）。
